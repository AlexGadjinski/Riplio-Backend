# Riplio

Riplio is a Reddit-inspired community platform where users create communities, share posts, comment in nested threads, and send "ripples" (up/down votes) across content. It includes full community moderation and a dedicated content-moderation microservice.

> **Main repository:** <MAIN_REPO_URL>

This repository contains the **main backend service** (REST API). The project is split across three repositories — see [Related repositories](#related-repositories).

## Features

- **Authentication & security** — JWT-based auth (register, login), stateless security, role-aware endpoints.
- **Communities** — create and manage communities, join/leave, members and roles (member, moderator, owner).
- **Posts & comments** — create posts with media, nested comments with soft-delete, per-item reply threads.
- **Ripples** — up/down voting (RISE/FALL) on posts and comments with aggregated scores.
- **Moderation** — ban/unban members, promote/demote moderators, transfer ownership, and a report queue backed by the moderation microservice.
- **Trending** — cached trending feed refreshed on a schedule.
- **Media uploads** — image/GIF/video handling with content-type detection.
- **Validation & error handling** — consistent field-level validation and structured error responses.
- **Scheduling & caching** — scheduled trending recomputation and cache eviction, plus a periodic moderation-service health check.

## Tech stack

- Java 21, Spring Boot 3.4.0 (Web, Data JPA, Security, Validation, Scheduling, Cache)
- MySQL
- JWT (jjwt 0.12.6)
- Cloudinary (media storage) + Apache Tika (file type detection)
- Lombok
- Maven
- Testing: JUnit, Spring Boot Test, JaCoCo (coverage), Checkstyle

## Architecture

```
riplio-frontend (React)
        |
        v
riplio-backend (this repo, :8080)  <----->  riplio-moderations-service (:8081)
        |                                             |
        v                                             v
     MySQL: riplio_app                        MySQL: riplio_moderations_service
```

The main backend owns users, communities, posts, comments and ripples. The moderation microservice owns reports and moderation decisions; the main backend integrates with it over HTTP and exposes the report endpoints to clients.

## Getting started

### Prerequisites

- Java 21
- Maven 3.9+
- MySQL 8+
- A Cloudinary account (for media uploads)

### Configuration

Create a local `application.yml` (or set environment variables) with your own values:

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/riplio_app
    username: your_db_user
    password: your_db_password
  jpa:
    hibernate:
      ddl-auto: update

app:
  jwt:
    secret: your_jwt_secret
    expiration: 86400000

cloudinary:
  cloud-name: your_cloud_name
  api-key: your_api_key
  api-secret: your_api_secret

moderation-service:
  base-url: http://localhost:8081
```

Create the database before first run:

```sql
CREATE DATABASE riplio_app;
```

### Run

```bash
./mvnw spring-boot:run
```

The API starts on `http://localhost:8080` with a base path of `/api/v1`.

### Test

```bash
./mvnw test
```

Coverage reports are generated by JaCoCo under `target/site/jacoco`.

## API overview

Base path: `/api/v1`

| Area        | Examples |
|-------------|----------|
| Auth        | `POST /auth/register`, `POST /auth/login` |
| Users       | `GET /users/me`, `PUT /users/me`, `PUT /users/me/avatar`, `GET /users/{username}` |
| Communities | `GET /communities`, `POST /communities`, `GET /communities/{id}` |
| Membership  | `POST /communities/{id}/members`, `PATCH /communities/{id}/members/{userId}` |
| Moderation  | `POST /communities/{id}/bans/{userId}`, `PUT /communities/{id}/owner` |
| Posts       | `POST /communities/{id}/posts`, `GET /posts/{id}`, `GET /posts/trending` |
| Comments    | `POST /posts/{postId}/comments`, `GET /comments/{id}/replies` |
| Ripples     | `POST /posts/{postId}/ripples`, `POST /comments/{commentId}/ripples` |
| Reports     | `POST /posts/{postId}/reports`, `GET /communities/{communityId}/reports` |
